# 📓 작업 기록 → Memo 앱 연동 지시문

각 프로젝트의 `CLAUDE.md` 맨 아래에 **아래 블록을 복사해 붙여넣으세요.**
`{{프로젝트}}` 부분만 그 프로젝트 이름으로 바꾸면 됩니다.

사용할 이름 (이미 정해진 것 — 새로 짓지 말 것):

| 폴더 | `{{프로젝트}}` |
|---|---|
| `ai-tarot-chat` | `타로` |
| `ai_stock_predictor_renewal` | `주식` |
| `news` | `뉴스` |
| `ebook` | `이북` |
| `emul` | `에뮬` |

---

## 붙여넣을 블록 (아래 ``` 안쪽 전체)

````markdown
## 📓 작업 기록 (Memo 앱 연동)

작업 기록을 아래 폴더에 마크다운으로 남긴다. 이 폴더는 Google Drive가
동기화하므로, 저장하면 사장님 폰·태블릿의 Memo 앱에 자동으로 나타난다.

```
/Users/jeawon/Library/CloudStorage/GoogleDrive-hellojeawon@gmail.com/내 드라이브/MindFlow/memos/
```

### ① 세션 시작 — 사장님 코멘트 먼저 확인

위 폴더에서 `tags`에 `프로젝트/{{프로젝트}}` 가 있는 `.md` 파일 중
**수정일 기준 최근 3개**를 읽는다. `## 코멘트` 섹션에 내용이 있으면
그 지시를 이번 세션에서 최우선으로 반영한다.

### ② 세션 종료 — 기록 생성

**반드시 새 파일을 만든다. 기존 파일은 절대 수정·삭제하지 않는다.**
사장님이 앱에서 달아둔 코멘트가 날아가고 동기화 충돌이 발생한다.

**ID 생성** (17자리 — 기존 메모는 6~7자리라 절대 충돌하지 않음):
```bash
node -e "console.log(Date.now()*10000+Math.floor(Math.random()*10000))"
```

**파일명**: `{ID}-{제목}.md`
제목에 `/ \ : * ? " < > |` 금지.

**파일 내용**:
```markdown
---
id: {위에서 생성한 ID}
title: [{{프로젝트}}] {이번 세션 한 줄 제목}
date: {ISO8601 — 예: 2026-07-29T14:20:00.000Z}
updated: {date와 같은 값}
tags: ["프로젝트/{{프로젝트}}"]
---

{한 줄 요약 — 반드시 첫 줄에}

## 이번 세션
- {한 일}

## 다음
- [ ] {다음에 할 일}

## 코멘트

#프로젝트/{{프로젝트}}
```

### ③ 지켜야 할 규칙

- **첫 줄 한 줄 요약은 필수.** 앱의 메모 목록과 홈 화면 카드에 이 줄이
  미리보기로 표시된다. 없으면 목록에서 무슨 내용인지 알 수 없다.
  `##` 헤더나 이미지로 시작하면 안 된다.
- **커밋 단위가 아니라 의미 단위로 요약한다.** "3개 파일 수정"이 아니라
  "로그인 실패 시 재시도 로직 추가" 처럼.
- **`## 다음`은 반드시 `- [ ]` 체크박스로.** 앱 홈의 "오늘의 할 일"이
  이 미완료 항목들을 모아서 보여주고, 프로젝트 카드의 진행률도
  `- [x]` / 전체 비율로 계산된다. 일반 불릿(`-`)으로 쓰면 안 잡힌다.
- **`## 코멘트`는 항상 빈 채로 남긴다.** 사장님이 앱에서 채우는 자리다.
- 사장님 코멘트를 반영했으면 다음 기록의 `## 이번 세션`에
  `코멘트 반영: ~` 로 명시한다.
- 특별히 남길 만한 인사이트가 있으면 `## 남긴 생각` 섹션을 자유롭게 추가한다.
  매번 억지로 채우지는 말 것 — 있을 때만.
- `tags`는 위 표의 이름 그대로 쓴다. 오타가 나면 앱에서 별개 프로젝트로
  갈라진다 (`프로젝트/에뮬` ≠ `프로젝트/에뮬레이터`).
- **본문 맨 끝에 `#프로젝트/{{프로젝트}}` 를 반드시 넣는다.** 프론트매터의
  `tags:` 만으로는 부족하다. 앱은 본문의 `#태그`를 진실로 보고, 메모를 열어
  한 글자라도 입력하면 본문 해시태그를 기준으로 `tags`를 다시 계산한다
  (memo.js의 syncMemoHashtags). 본문에 해시태그가 없으면 그 순간 태그가
  지워지고 노트가 프로젝트에서 빠진다.
````

## 실제 예시

```markdown
---
id: 17538812458730001
title: [타로] 런칭 준비 — 프롬프트 최적화
date: 2026-07-29T14:20:00.000Z
updated: 2026-07-29T14:20:00.000Z
tags: ["프로젝트/타로"]
---

광고 연동만 남기고 런칭 준비 마무리 단계.

## 이번 세션
- D 시안 디자인 적용
- MBTI 연동 추가
- 세라피나 프롬프트 톤 조정 (토큰 30% 감소)

## 다음
- [ ] AdMob 실계정 연결
- [ ] 배포 스크립트 .env 정리
- [x] 스토어 스크린샷 5장

## 남긴 생각
프롬프트를 짧게 하니 응답 속도 체감이 확 달라짐. 다른 프로젝트에도 적용해볼 것.

## 코멘트

#프로젝트/타로
```

이 파일이 앱에서 이렇게 보인다:

- **홈 "이어서 하기"** → `타로` 카드, 부제 `광고 연동만 남기고 런칭 준비 마무리 단계.`,
  진행률 `할 일 1/3 · 33%`, 타일 `메모 1 / 할 일 3`
- **홈 "오늘의 할 일"** → `AdMob 실계정 연결`, `배포 스크립트 .env 정리`
- **사이드바 태그 트리** → `프로젝트 ▸ 타로`
- **캘린더 7월 29일** → `이날 남긴 흔적`에 이 노트가 시각과 함께 표시

---

## 사장님이 코멘트 다는 법

1. 앱에서 해당 기록을 연다
2. `## 코멘트` 아래에 하고 싶은 말을 적는다
3. 다음 세션에 그 프로젝트 에이전트가 읽고 반영한다
